# C to C — Chat to Crane

웹 참여자의 채팅을 Unity 크레인 조작으로 연결한 참여형 교육 콘텐츠입니다. 채팅을 읽고 표시하는 데서 끝내지 않고, 방향 입력·집기 요청·획득 확인을 하나의 플레이 흐름으로 연결했습니다.

## My Role

- 채팅을 크레인 조작으로 연결하는 아이디어 제안.
- Unity 클라이언트 REST 방 생성·QR 응답 처리, STOMP 연결·구독, 수신 큐와 JSON 정규화 구현.
- 채팅 카드·프로필 표시, 한국어·영어 방향어 처리, 누적 입력 기반 집기 요청·투표 재개 구현.
- 팀원이 구현한 크레인 이동·집기·획득 패널에 방향 이벤트와 완료 이벤트를 연결하는 후속 수정.

백엔드 API·웹 참여 페이지·크레인 물리의 기반 구현은 팀 구성요소입니다. STOMP 전송은 Netina 라이브러리를 사용했습니다. 전체 기획·설계 또는 공동 시스템 전체를 개인 단독 구현으로 포함하지 않습니다.

## Core Systems

### 방 생성부터 실시간 수신까지

REST 응답의 방 ID로 STOMP 구독 주소를 만들고 QR 이미지 표시로 연결합니다. 응답 data의 문자열·객체 형태와 QR URL 누락에 대한 분기를 구현했습니다. 서버 API와 참여 페이지는 팀원이 제공한 구성요소입니다.

### 수신 시점과 UI 갱신 시점 분리

STOMP 콜백의 JSON을 잠금으로 보호한 큐에 넣고 Unity Update에서 파싱·이벤트 전달을 수행합니다. 응답 형태에 따라 기본 응답을 직접 전달하거나, 정규화한 채팅 데이터를 별도 큐로 전달합니다. 큐에는 프레임당 처리량 제한이 없어 대량 메시지 부하에 대한 성능 보장을 주장하지 않습니다.

### 채팅을 게임 명령으로 변환

방향 별칭을 정규화하고 유효한 입력마다 즉시 크레인 이동 명령을 보냅니다. 누적 입력은 집기 트리거와 그래프 표시에 사용하며 다수결로 이동 방향을 정하지 않습니다. 최종 씬 저장값은 20건에서 집기 요청, 복구 타임아웃 10초입니다. 코드 기본 임계값은 40건입니다.

집기 중에도 채팅 카드는 표시하고 방향 투표는 중단합니다. 획득 확인 또는 실패 경로의 완료 이벤트로 재개하고, 누락 시 타임아웃으로 투표 수신을 복구합니다. 복구 타임아웃이 물리 집기 자체를 취소하는 것은 아닙니다.

### 채팅 UI와 획득 연동

채팅 목록은 저장 설정상 최대 50개를 유지하도록 오래된 항목을 제거합니다. 프로필 다운로드와 선택적 URL 캐시를 구현했으며, 채팅 프리팹의 캐시는 비활성화되어 있습니다. 폭탄 획득 시 방향 입력으로 모은 닉네임 목록에서 하나를 선택해 팀원의 획득 패널에 표시하도록 수정했습니다. 같은 닉네임이 여러 번 등록될 수 있으므로 사용자별 균등 추첨은 아닙니다.

이 쇼케이스에는 실행 빌드·씬·에셋·외부 DLL·인증 설정을 포함하지 않습니다. 원본을 실행하려면 Unity와 Netina STOMP 관련 라이브러리, Newtonsoft.Json, UI·씬 참조가 필요합니다. 실서버 모드는 팀의 REST/STOMP 서비스와 유효한 방 생성 식별자에 의존합니다. 원본의 GameSettingScene에는 mock 채팅 설정이 저장되어 있지만 이 문서와 샘플만으로 실행할 수는 없습니다.

검토에서는 코드·Git 이력·씬 저장값과 발췌 21개 일치, 문서 내부 링크 23개 연결을 확인했습니다. C# 발췌의 문법 검사와 원본 ChatModels.cs의 별도 .NET 컴파일·방향 파서 입력 12개 테스트를 통과했습니다. 발췌 문법 검사는 원본 클래스 문맥을 대신한 임시 클래스에서 수행하며, 누락된 의존성의 타입 검증은 포함하지 않습니다. Unity 전체 컴파일·Play Mode·외부 서버 연동은 실행하지 않았습니다.

소개서 링크는 기존 자료에서 가져왔으며 현재 접근 가능 여부와 영상 내용은 확인하지 못했습니다. 팀 저장소는 검토에 사용한 GitHub 연결에서 404를 반환하여 원본 링크의 외부 접근을 확인하지 못했습니다. 공개 샘플은 원본 저장소 접근 없이 읽을 수 있습니다.
