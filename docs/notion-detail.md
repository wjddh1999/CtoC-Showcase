# C to C | Chat to Crane

실시간 웹 채팅을 Unity 크레인 조작으로 변환하는 참여형 교육 콘텐츠를 완성했습니다. 참여자의 방향 입력이 크레인 움직임으로 이어지고, 누적 입력 후 물건을 집어 설명을 확인하는 흐름을 구현했습니다.

**개발 기간:** 2026.06.17–2026.06.19 · 2박 3일 해커톤  
**팀 구성:** 5인  
**완료 상태:** 완성  
**기술:** Unity 6000.5.0f1 · C# · REST API · WebSocket/STOMP · uGUI/TMP

## 담당 역할

채팅을 크레인 조작으로 연결하는 아이디어를 제안하고, Unity 클라이언트의 통신·수신 처리·채팅 UI·방향 명령 전달을 구현했습니다. 팀원이 만든 크레인 이동·집기와 획득 패널에는 이벤트 기반 연결과 완료 처리를 추가했습니다.

백엔드와 웹 참여 페이지, 크레인 물리의 기반 구현은 팀 구성요소입니다. STOMP 통신은 Netina 외부 라이브러리를 활용했습니다.

## 1. 방 생성 결과를 구독과 참여 안내로 연결

**문제:** Unity가 웹 채팅을 받으려면 서버가 만든 방의 ID를 구독 주소에 반영하고, 참여자가 들어갈 수 있는 QR을 표시해야 했습니다.

**설계 판단:** 방 생성이 끝난 뒤 구독을 시작하도록 순서를 고정했습니다. 방 생성 응답의 data가 문자열 또는 객체인 경우를 구분하고, QR URL이 없으면 방 ID로 대체 URL을 구성하도록 했습니다.

**구현:** CreateRoomAsync 결과를 ConnectAndSubscribeAsync에서 받아 구독 주소와 QR 로딩에 전달합니다. QR 다운로드는 타임아웃을 적용하고 새 Sprite를 표시하기 전에 이전 QR Sprite·Texture를 정리합니다. 구독은 주소별 예외를 처리합니다.

**확인 결과:** 방 생성 응답을 QR 표시와 STOMP 구독으로 연결했습니다.

[방 생성·QR 코드 발췌](../samples/01-room-and-qr.md)

## 2. 네트워크 수신과 Unity UI 실행 시점 분리

**문제:** 네트워크 콜백과 Unity UI 갱신은 실행 시점이 다르므로 수신 콜백에서 직접 게임 오브젝트를 다루지 않는 전달 경로가 필요했습니다.

**설계 판단:** 콜백은 데이터를 큐에 넣고 Update가 파싱·이벤트 전달을 수행하도록 분리했습니다. 공유 큐의 접근은 lock으로 보호했습니다.

**구현:** 수신 JSON 큐와 정규화된 채팅 큐를 사용합니다. 기본 ChatResponse 형식은 Update의 파싱 중 직접 전달하고, 유연 파싱 결과는 채팅 큐에 넣어 같은 Update에서 전달합니다. 배열과 data 래퍼, 메시지·닉네임·이미지 필드의 별칭을 공통 모델로 변환합니다.

**확인 결과:** 수신 콜백과 Unity 프레임 처리를 분리하고, 서로 다른 응답 형태를 공통 채팅 모델로 처리했습니다.

[수신 큐 발췌](../samples/02-main-thread-queue.md) · [JSON 정규화 발췌](../samples/03-json-normalization.md)

## 3. 일반 채팅과 방향 명령을 구분하고 집기 흐름 연결

**문제:** 일반 대화는 계속 보여주면서 방향 메시지만 게임 입력으로 사용하고, 집기 중 들어오는 입력이 진행 중인 조작에 섞이지 않게 해야 했습니다.

**설계 판단:** 정규화한 방향 별칭과 정확히 일치하는 메시지만 명령으로 인정했습니다. 이동은 입력마다 즉시 전달하고, 누적 건수는 집기 요청과 투표 그래프 표시에 사용했습니다.

**구현:** 한국어·영어·화살표를 ChatDirection으로 변환해 CraneEventHub로 전달합니다. 최종 씬은 20건에서 집기를 요청하며 코드 기본값은 40건입니다. 집기 요청 후 방향 투표는 멈추지만 채팅 UI는 계속 표시합니다. 획득 패널 확인 또는 집기 실패 경로의 완료 이벤트로 재개하고, 완료가 누락되면 설정된 10초 후 투표 수신을 복구합니다.

**확인 결과:** 방향 입력마다 이동 명령을 전달하고, 누적 입력에 따른 집기 요청과 완료 후 투표 재개를 연결했습니다. 타임아웃은 투표 수신을 복구합니다.

[방향 파서](../samples/05-direction-parser.md) · [집기 흐름](../samples/04-direction-and-pickup.md) · [공동 크레인 연동 수정](../samples/07-crane-integration.md)

## 4. 메시지 카드와 획득 결과 표시

**문제:** 빠르게 들어오는 채팅을 카드로 표시하고, 프로필 이미지 요청과 획득 결과의 표시를 게임 흐름에 연결해야 했습니다.

**설계 판단:** 카드가 데이터 표시와 이미지 요청을 맡고, 컨트롤러가 목록 관리와 명령 처리를 맡도록 분리했습니다. 획득 패널 자체를 다시 만들지 않고 팀원 구현에 완료 이벤트와 폭탄 결과 표시를 추가했습니다.

**구현:** 카드에 닉네임·내용을 적용하고 프로필 이미지 코루틴을 처리합니다. 채팅 목록은 설정상 최대 50개를 유지하도록 오래된 항목을 제거합니다. URL별 이미지 캐시는 옵션으로 구현했으며 프리팹에서는 꺼져 있습니다. 폭탄 획득 시 해당 라운드의 방향 입력으로 수집한 닉네임 목록에서 하나를 선택해 설명에 붙입니다.

**확인 결과:** 채팅 카드·프로필 표시와 목록 제한을 구현하고, 팀원의 획득 패널에 완료 처리와 폭탄 결과 표시를 연결했습니다. 닉네임 후보는 방향 입력마다 수집하므로 중복될 수 있습니다.
